# Проверка распознавания на 30 изображениях

Дата: 14 сентября 2026. До изменений: версия `15edb84`. После: два режима распознавания и оптимизация обработки фотографий. Все измерения выполнены локально в Chromium с OpenCV.js и Tesseract.js; фотографии не отправлялись в OCR-сервисы.

| Пропущенные числа в этом режиме                                     |        325 |        109 |
| Неверно прочитанные числа в этом режиме                             |         67 |         92 |

В основной режим теперь попадают ранее удалённые рукописные цифры, часть которых OCR читает неверно. Поэтому число **неверно прочитанных** цифр выросло, хотя пропусков стало существенно меньше. Число полностью точных полей не увеличилось: некоторые сложные примеры стали гораздо лучше, но им всё ещё нужна ручная проверка. Для фотографий с ответами ручкой следует выбирать «Только печатные».

На 23 изображениях без вписанных ответов (включая четыре размытых снимка и один сложный курсивный шрифт) распознано **594 из 635 чисел**, вместо 453 из 635. Это **93,5% по исходным числам**, а не процент полностью решаемых без исправления задач.

Пользовательское изображение 16×16 с синими цифрами проверяется отдельно: **100 из 100 исходных чисел**, без ложных заполнений. Оно не включено в эти 30 интернет-изображений.

## Методика и ограничения

- Ровно 30 различных файлов, скачанных из интернета. Варианты, созданные локально из одного файла, не засчитывались как дополнительные изображения. Два снимка показывают одну и ту же задачу; оба первоначально попали в одну группу проверки.
- 20 изображений сначала использовались для настройки, 10 — для отложенного контроля. Первая отложенная проверка выявила ложные числа на фактурной бумаге. Затем они были исправлены с использованием этих примеров. **Финальный результат получен на известном наборе и не является независимой оценкой точности на любых новых фотографиях.** Первая отложенная проверка сохранена отдельно.
- Проверяется автоматическое определение границ и распознавание. Все эти интернет-примеры — 9×9; эталонный размер явно задан измерителю, правильность предложения размера записывается в JSON. Для 16×16 и составных полей есть отдельные браузерные сценарии.
- Эталонные числа используются только для измерения ошибок. Алгоритм не получает названия файлов, эталоны или ответы решателя для исправления OCR. Нейросеть Tesseract не переобучалась: улучшены подготовка изображения, фильтры и повторное чтение сомнительных клеток.
- При измерении фильтра на полностью рукописном `expert` эталон печатных чисел пуст; это проверка удаления рукописи, а не успешного восстановления исходной задачи.
- Исправлены три несоответствия в сопоставлении исходных заполненных/незаполненных фотографий датасета. Числа переписаны непосредственно с изображений; изменения описаны в источниках. Базовые результаты пересчитаны по тем же эталонам.

## Что изменилось

- По умолчанию «Все числа»: сохранение синей/красной печати и тонких символов.
- «Только печатные» включается явно перед OCR и сбрасывается при загрузке следующей фотографии. Сохранён фильтр синих записей, добавлены красные. Для густо заполненных полей сравнивается размер символов, чтобы отсеивать мелкие ответы ручкой.
- Повторный поиск слабоконтрастной сетки, щадящая подготовка небольших клеток, очистка с учётом толщины штриха.
- Контраст кандидатов сравнивается с другими символами того же поля, чтобы отбрасывать шум бумаги без жёсткого единого порога яркости.
- Дополнительное чтение сомнительной клетки 9×9 как одиночной цифры. Проверка двух замкнутых контуров больше не заменяет уверенно прочитанную `4` на `8`.

## Повторный запуск

```bash
node scripts/fetch-ocr-corpus.mjs
OCR_CORPUS=1 npm run test:e2e -- tests/ocr-corpus.spec.ts --project=desktop
node scripts/report-ocr-corpus.mjs /tmp/sudoku-ocr-current
```

Проверки ограничивают число ошибок и ложных заполнений отдельно для каждого изображения. Нулевой допуск используется для точно распознаваемых примеров. Успех тестового прогона означает соблюдение этих границ; он не означает безошибочное чтение всех 30 изображений.
