# Локальные границы блоков и клеток

Версия 0.2.9, 14 сентября 2026 года.

Раньше после исправления перспективы использовались общие координаты вертикальных и горизонтальных линий на всё поле. На изогнутом листе разделитель меняет положение вдоль фотографии. Поэтому обрезка могла захватить соседнюю клетку или отрезать первую цифру двузначного числа, например прочитать `15` как `5`.

## Обработка фотографии

1. Исправляется общая перспектива по четырём внешним углам. Сохраняется запас вокруг поля: изогнутая рамка может выходить за четырёхугольник между углами.
2. На фотографии до фильтрации рукописных пометок прослеживаются разделители. Поиск предпочитает длинные непрерывные линии коротким штрихам цифр. Общая проекция служит только начальным приближением.
3. Строится сетка пересечений: каждый блок 3×3 или 4×4 получает собственные четыре угла, каждая клетка — свои вершины. Соседние блоки используют общие вершины, чтобы на стыках не было разрывов.
4. Если тонкий разделитель отсутствует или ненадёжен, его положение восстанавливается по границам соответствующего блока. Внешняя рамка проверяется по кривизне соседних линий, чтобы не захватить край страницы или декоративную рамку.
5. Изображение выравнивается по полученной сетке. OCR, миниатюра клетки в редакторе и переключатель «Фото / Поле» используют одно выровненное изображение. Границы полной клетки для сравнения отделены от небольшого внутреннего отступа, применяемого при OCR.

Размер блока передаётся из структуры задачи. Для составных судоку обработка выполняется отдельно для каждого поля 9×9; общая клетка по-прежнему имеет одно значение. Реализованные форматы приложения остаются прежними: 9×9, 16×16 и пересекающиеся поля 9×9.

На уже ровных сетках дополнительное преобразование не применяется. Если геометрия получилась ненадёжной, пересекающейся или чрезмерно растянутой, сохраняется исходное выравнивание, а обнаруженная неоднозначность отмечается для проверки. Алгоритм рассчитан на плавное искривление листа; складки, закрытые цифры и ошибочно выбранные внешние углы могут потребовать нового снимка или ручной правки. Режимы «Все числа» и «Только печатные» сохранены, правила решателя не используются для угадывания OCR.

## Проверки

Контрольные изображения создаются независимо от алгоритма геометрии: к напечатанным задачам применяется перспективный наклон и плавная деформация до 0,38 ширины клетки. Эталонные числа используются только тестом.

| Контрольный пример                        | Ошибок до изменения геометрии | Ошибок после |
| ----------------------------------------- | ----------------------------: | -----------: |
| Изогнутая сетка 9×9, 30 исходных чисел    |                             6 |            0 |
| Изогнутая сетка 16×16, 104 исходных числа |                            43 |            0 |

В примере 16×16 воспроизведено превращение `15` в `5` (строка 11, столбец 15). После выравнивания число распознаётся целиком. Это воспроизведение класса ошибки, а не измерение по одному скриншоту редактора.

- Шесть вариантов изображений проверены в Chromium и WebKit: оба размера, искривление, пропущенная тонкая линия внутри блока и только перспективный наклон. Проверяется полное совпадение всех клеток, включая пустые.
- Численные тесты проверяют координаты вершин, общие границы блоков, неточные начальные координаты линий и отсутствие достаточных признаков сетки.
- Браузерные сценарии проверяют оба режима OCR, синие печатные цифры, реальную фотографию 16×16 и совпадение фото с полем при масштабировании и навигации по восьми полям. Всего в целевом прогоне прошли 34 браузерных сценария.
- Повторно выполнены 37 проверок на прежних 30 интернет-изображениях: результаты по каждому изображению сохранились. В режиме «Все числа» верно прочитано 944 из 1145 чисел, требуется 203 исправления клеток; при фильтрации — 176 из 181 печатного числа и 17 исправлений. Успешный регрессионный прогон не означает безошибочного распознавания всех фотографий. [Измерения](local-geometry.json), [описание набора и ограничений](README.md).

```sh
npm test
npm run test:e2e -- tests/grid-curvature.spec.ts tests/photo-alignment.spec.ts tests/recognition-modes.spec.ts tests/photo.spec.ts --project=desktop --project=webkit

```

Для локальной приёмки обновите страницу и заново загрузите фотографию: ранее распознанная задача автоматически не обрабатывается повторно.
