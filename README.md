# SudokuMaster

Сайт на русском языке для распознавания и решения классических судоку **9×9** и **16×16**. Работает на компьютере и телефоне. Обработка фотографий, поиск решения и экспорт PNG выполняются в браузере, без бэкенда и стороннего OCR API.

## Локальный запуск

Нужен Node.js 22.12+ или 24+ и npm. Проект проверен на Node.js 24.

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно `http://localhost:5173`). Для проверки с телефона подключите его к той же Wi-Fi сети и откройте адрес `Network` из вывода Vite. Изображение выбирается через системный выбор файла; доступ к отдельному Camera API не нужен.

При установке зависимостей `postinstall` копирует OpenCV, три совместимые сборки OCR WASM, OCR worker и модель распознавания в `public/vendor`. Во время работы приложения они загружаются с того же сайта. Папка генерируется и не хранится в Git. Если установка выполнялась с `--ignore-scripts`, отдельно запустите `npm run prepare:assets`.

## Как пользоваться

1. Загрузите JPG, PNG или WebP до 25 МБ. Также можно начать с примера или ввести числа вручную.
2. Проверьте размер поля и четыре угла; при необходимости поверните фото. Обрабатывается одно выбранное поле.
3. После распознавания сверьте числа с оригиналом. Нажатие на клетку показывает её фрагмент на фотографии. Можно исправлять любые значения; жёлтые отметки помогают найти сомнительные результаты, красные показывают повторы.
4. В карточке под полем нажмите «Я проверил(а) числа по фотографии». Кнопка исчезнет, и рядом станет доступна «Решить судоку» — нажмите её для запуска. Здесь же можно показать оригинал и выбрать скорость. Если изменить число, проверку потребуется подтвердить заново. Во время решения доступны пауза, продолжение и остановка.
5. Скачайте PNG с готовой сеткой. При нескольких решениях изображение отмечено как один из возможных вариантов; при незавершённой проверке единственность не заявляется.

На телефоне поле 16×16 можно увеличить. Ввод доступен с клавиатуры и через панель чисел 1–16. Стрелки клавиатуры перемещают выделение, Backspace/Delete очищают ввод.

Синие записи ручкой и мелкие кандидаты подавляются эвристиками. Чёрные рукописные ответы, сильная кривизна листа, перекрытые или размытые числа могут требовать ручного исправления. Проверка фотографии обязательна даже при высокой уверенности распознавания.

## Устройство приложения

- **React + TypeScript + Vite**: интерфейс, редактирование, сравнение с фотографией, управление вычислениями.
- **OpenCV.js**, в отдельном classic worker: поиск сетки, определение размера, коррекция перспективы, фильтрация цветных заметок, выделение клеток и печатных символов.
- **Tesseract.js**: последовательное распознавание непустых клеток одним worker, ограниченный набор символов `0–9`, проверка результата в диапазоне `1–size`.
- **Решатель TypeScript**, в отдельном module worker: битовые маски, одиночные кандидаты, единственные позиции числа, выбор клетки с минимумом кандидатов, поиск с возвратом. До двух решений для проверки единственности.
- **События поиска**: постановка, гипотеза, откат, найденное решение. Интерфейс запрашивает ограниченные порции, поэтому очередь не растёт при медленной анимации. После первого решения отображаемое поле сохраняется, а проверка единственности идёт в фоне.
- **Лимит**: 30 секунд активных вычислений, без ожидания анимации. Продолжение добавляет ещё 30 секунд. Достижение лимита не означает отсутствия решения.
- **PNG**: отрисовка из данных задачи и решения на Canvas, независимо от размера экрана.

Модель задачи, распознавание и правила решения разделены. В первой версии реализованы только классические правила; диагональные, Killer и нерегулярные судоку пока не поддерживаются. Учётные записи, история задач и гарантированный офлайн-запуск отсутствуют.

## Проверки

```sh
npm test
npm run build
npx playwright install chromium firefox webkit
npm run test:e2e
# Всё вместе после установки браузеров:
npm run verify
# Проверка именно статической сборки (сначала npm run build):
npm run test:e2e -- --config=playwright.preview.config.ts
```

Vitest проверяет оба размера, гипотезы и восстановление состояния, сохранение исходных чисел, единственность, отсутствие решений, конфликты и геометрию углов. Playwright проверяет реальные браузеры: Chromium, Firefox и WebKit в режиме iPhone; ручной ввод, паузу, отмену, PNG, загрузку и распознавание фотографии. Мобильная эмуляция не заменяет отдельную приёмку на физическом телефоне.

Дополнительно проверяются продолжение поиска после лимита вычислений, ошибка загрузки OCR-модели и поворот фотографии. Исходники форматируются командой `npm run format`; `npm run verify` также проверяет форматирование.

Распознавание проверяется на сгенерированных печатных полях и исходной фотографии 16×16 из обсуждения проекта. Тест фотографии записывает отчёт о правильно распознанных печатных числах, ложных числах и требуемых исправлениях. Тест приватности проверяет отсутствие запросов к внешним HTTP-сервисам во время полного сценария OCR.

На контрольном снимке из журнала в Chromium и WebKit правильно распознано 101 из 104 печатных чисел, дополнительно ошибочно включено 5 рукописных значений: требуется исправить 8 клеток. Это результат на одном снимке, а не обещание точности для других фотографий. Чистые контрольные поля обоих размеров распознаны точно, включая обычный, нежирный шрифт 16×16.

## Сборка и публикация

```sh
npm run build
npm run preview
```

Готовый сайт находится в `dist/`. Сборка включает OCR-модель и локальные WASM-ресурсы. Открывать `index.html` напрямую через `file://` не следует: worker и WASM требуют HTTP-сервера.

Для **Cloudflare Pages**:

- Укажите корневую папку проекта: `SudokuV2`, если репозиторий включает родительский Python-прототип; иначе корень репозитория.
- Версия Node.js: 24. Команда сборки: `npm run build`. Выходная папка: `dist`.
- Установка зависимостей должна выполнять `postinstall`.
- Functions, секреты и база данных не нужны. Каждый публикуемый файл меньше ограничения Pages в 25 MiB.
- После публикации проверьте обработку фотографии и загрузку PNG уже по публичному HTTPS-адресу.

Для GitHub Pages задайте Vite `--base=/имя-репозитория/` при сборке; имена и пути ресурсов вычисляются относительно базового адреса сайта.

## Данные примера и документы

- `src/data/example16.json` — 104 печатных числа из предоставленного примера, извлечённые из существующего `../full.py` и сверенные с фотографией.
- `tests/fixtures/magazine16.png` — исходный снимок с рукописными заметками, регрессионный пример OCR. Не включается в сборку публичного сайта.
- `SudokuMaster-plan.pdf` — согласованный план проекта.

Уведомления о лицензиях встроенных библиотек находятся в `public/vendor/licenses` после подготовки ресурсов. Данные OCR предоставляются пакетом `@tesseract.js-data/eng`; исходная модель Tesseract распространяется под Apache-2.0.
