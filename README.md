# SudokuMaster

Рабочий интерфейс на русском языке для съёмки, распознавания и решения классических судоку **9×9**, **16×16** и **составных задач из пересекающихся полей 9×9**. Работает на компьютере и телефоне. Обработка фотографий, поиск решения и экспорт PNG выполняются в браузере, без бэкенда и стороннего OCR API.

## Локальный запуск

Нужен Node.js 22.12+ или 24+ и npm. Проект проверен на Node.js 24.

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно `http://localhost:5173`). На `localhost` доступны загрузка и съёмка встроенной или подключённой камерой. Для загрузки фото с телефона подключите его к той же Wi-Fi сети и откройте адрес `Network` из вывода Vite. Для камеры на телефоне требуется доверенный HTTPS — см. ниже.

При установке зависимостей `postinstall` копирует OpenCV, три совместимые сборки OCR WASM, OCR worker и модель распознавания в `public/vendor`. Во время работы приложения они загружаются с того же сайта. Папка генерируется и не хранится в Git. Если установка выполнялась с `--ignore-scripts`, отдельно запустите `npm run prepare:assets`.

## Как пользоваться

1. На первом экране выберите **«Сделать фото»** или **«Загрузить фото»**. Поле сразу видно; по умолчанию оно пустое. Поддерживаются JPG, PNG и WebP до 25 МБ.
2. Камера открывается внутри SudokuMaster и запрашивает разрешение только после нажатия. Поместите всё судоку в кадр, нажмите «Снять фото», затем «Использовать фото». Неудачный снимок можно переснять. При нескольких камерах доступен переключатель; микрофон не используется.
3. Проверьте найденную схему и при необходимости поверните фото. Для классического судоку уточните размер и четыре угла. Для составного — проверьте пронумерованные поля и общие блоки, затем нажмите «Схема верна — распознать числа». «Исправить схему» позволяет двигать углы всего расположения или отдельного поля, добавлять и удалять поля. Если автоматическое определение не удалось, выберите готовую схему.
4. После распознавания сверьте числа через переключатель «Фото / Поле». Фото выровнено по тем же клеткам: переключение сохраняет размер, прокрутку, масштаб и выбранное поле составной задачи. Кнопки «− / +» меняют масштаб от 25% до 200%; нажатие на процент возвращает 100%. Любую клетку можно исправить напрямую. Кнопка «Правка» открывает фрагмент фотографии и цифровую клавиатуру. «Следующая сомнительная клетка» переводит к очередному месту для проверки, включая другое поле составной задачи. Янтарные отметки показывают сомнительные клетки, красные — конфликты.
5. В панели действий нажмите «Я проверил(а) числа по фотографии». Кнопка исчезнет, и автоматически начнётся проверка судоку без показа ответа. После проверки станет доступна «Решить судоку», если у задачи есть решение. Исправление любого числа требует повторного подтверждения. На компьютере действия находятся справа от поля, на телефоне — в нижней закреплённой панели.
6. Нажмите «Решить судоку». По умолчанию используется быстрый режим без искусственных задержек. Замедление, статистика и объяснения доступны через «Ещё → Настройки решения» или «Подробности». Скорость сохраняется между задачами в текущей вкладке, после перезагрузки снова выбирается быстрый режим.
7. Нажмите янтарную кнопку **«Сохранить решение»**, чтобы скачать изображение с готовой сеткой. Синяя кнопка **«Новая задача»** открывает выбор съёмки или загрузки следующего фото. Синие числа — найденные, графитовые — исходные. При нескольких решениях изображение отмечено как один из возможных вариантов; при незавершённой проверке единственность не заявляется.

Примеры, ручной ввод, очистка и настройки находятся в меню **«Ещё»**. Для ручного ввода выберите «Ввести вручную», перенесите условие и нажмите **«Я заполнил числа»**. Это автоматически запустит проверку без показа ответа. Пустое поле подтвердить нельзя; сначала нужно ввести хотя бы одно число. Справка открывается из шапки.

**Автоматическая проверка после подтверждения чисел** показывает явный цветной статус: **зелёный** — ровно одно решение, **красный** — конфликт исходных чисел или отсутствие решений, **жёлтый** — несколько решений. Промежуточные цифры и найденный ответ не передаются из рабочего потока в интерфейс, сохранение решения не предлагается. Проверка всегда быстрая, независимо от выбранной скорости анимации. При исчерпании 30 секунд результат остаётся неопределённым: проверку можно продолжить или остановить. После завершения можно редактировать условие либо отдельно нажать «Решить судоку»; при конфликте или отсутствии решений эта кнопка недоступна. Любая правка сбрасывает результат проверки и требует повторного подтверждения как для фотографии, так и для ручного ввода. Встроенные готовые примеры можно сразу решать.

Для составных задач доступны примеры из двух, пяти («Самурай») и восьми полей. На телефоне выбранное поле 9×9 показывается крупно, карта и список переключают поля. «Вся задача» открывает общую схему с прокруткой и масштабированием. Общая клетка хранится один раз: правка видна в обоих связанных полях. Сохранение всегда включает всю композицию. «Очистить поле» сохраняет выбранную геометрию для ручного ввода.

На телефоне поле занимает основную часть экрана: зум и «Фото / Поле» собраны в одну строку, нижняя панель показывает действие текущего шага, а настройки доступны в меню «Ещё». Подтверждение фотографии сокращено до «Я проверил(а) числа»; значок списка с числом открывает очередную сомнительную клетку. Сохранение и новая задача стоят рядом. Схема составного судоку открывается кнопкой «Схема», а выбор поля остаётся над сеткой. В горизонтальном положении панель действий находится справа. Поле 16×16 можно увеличить. Ввод доступен с клавиатуры и через панель чисел 1–16. Стрелки клавиатуры перемещают выделение, Backspace/Delete очищают ввод.

Перед распознаванием доступны два режима. **«Все числа»** включён по умолчанию для каждой новой фотографии: сохраняет числа любого цвета и тонкие штрихи. **«Только печатные»** пользователь выбирает явно для заполненной задачи: он ориентируется на крупные чёрные цифры, подавляет синие и красные записи, тонкие штрихи и мелкие пометки. Типичный размер, темнота и толщина печати оцениваются по самому полю; цвет сравнивается с бумагой, чтобы учитывать освещение. Остатки рамки не считаются признаком пропущенной цифры. Это эвристики: крупные чёрные рукописные ответы могут остаться, а часть печатных чисел — пропасть. Сильная кривизна листа, необычный курсивный шрифт и размытие также могут требовать ручного исправления. Проверка фотографии обязательна в обоих режимах. [Проверки фильтра и отметок сомнения](docs/ocr/printed-confidence.md).

## Камера и HTTPS на телефоне

Съёмка использует `navigator.mediaDevices.getUserMedia` и работает на **localhost** либо по **HTTPS**. Обычный адрес вида `http://192.168.x.x:5173` позволяет загружать фото, но браузер не разрешает камеру. При отказе в разрешении, отсутствии или занятости камеры приложение объясняет причину и предлагает загрузку. После снимка, закрытия окна, смены камеры и ухода со страницы видеотреки останавливаются.

Vite поддерживает необязательные пути к локальному сертификату и ключу:

```sh
SUDOKU_HTTPS_CERT=.certs/local.pem SUDOKU_HTTPS_KEY=.certs/local-key.pem npm run dev
```

Нужно указать оба файла. Сертификат должен включать имя или IP-адрес, который открывается на телефоне, и быть выдан центром сертификации, которому доверяет устройство. Для локального центра установите его корневой сертификат на тестовый телефон и включите доверие в настройках устройства; закрытый ключ на телефон не переносите. После этого открывайте адрес `https://...:5173`. Файлы `.certs/`, `*.pem` и `*.key` исключены из Git. Без этих переменных сохраняется обычный HTTP-запуск. На публичном HTTPS-сайте локальные сертификаты не нужны.

Камера имеет экран предпросмотра и повторной съёмки. Отмена не заменяет текущую задачу. Предпросмотр и JPEG-снимок не зеркалятся; обработка выполняется тем же способом, что и для загруженного файла.

## Устройство приложения

- **React + TypeScript + Vite**: интерфейс, редактирование, сравнение с фотографией, управление вычислениями.
- **CameraDialog + MediaDevices + Canvas**: съёмка без микрофона, выбор устройства, освобождение видеотреков и передача JPEG в общий процесс распознавания.
- **Топология**: координаты полей, уникальные клетки, общие строки/столбцы/блоки и обратные связи ограничений. Схема с фотографии занимает 21×33 позиции и содержит 576 клеток; пустоты в решатель не попадают.
- **OpenCV.js**, в отдельном classic worker: поиск классической сетки либо контуров клеток и связанной решётки, повторный поиск слабоконтрастных границ, проверка пересечений, определение размера, коррекция перспективы, два режима выделения чисел. Очистка учитывает толщину штрихов; фильтрация цветных заметок включается только в режиме «Только печатные».
- **Локальная геометрия фотографии**: отдельные координаты блоков 3×3 / 4×4 и клеток внутри них, выравнивание плавно изогнутых линий, восстановление пропущенных тонких разделителей по своему блоку. OCR и сравнение «Фото / Поле» используют одно выровненное изображение. [Алгоритм и проверки](docs/ocr/local-geometry.md).
- **Tesseract.js**: последовательное распознавание непустых клеток одним worker, ограниченный набор символов `0–9`, проверка результата в диапазоне `1–size`. Для одиночной восьмёрки дополнительно проверяются два замкнутых контура; несовпадение с OCR отмечается для ручной проверки. Правила судоку не используются для подмены распознанных чисел.
- **Решатель TypeScript**, в отдельном module worker: битовые маски, одиночные кандидаты, единственные позиции числа, выбор клетки или позиции числа с минимумом кандидатов, поиск с возвратом. До двух решений для проверки единственности.
- **События поиска**: постановка, гипотеза, откат, найденное решение. Интерфейс запрашивает ограниченные порции, поэтому очередь не растёт при медленной анимации. После первого решения отображаемое поле сохраняется, а проверка единственности идёт в фоне.
- **Лимит**: 30 секунд активных вычислений, без ожидания анимации. Продолжение добавляет ещё 30 секунд. Достижение лимита не означает отсутствия решения.
- **PNG**: отрисовка из данных задачи и решения на Canvas, независимо от размера экрана.

Модель задачи, распознавание и правила решения разделены. Реализованы классические правила и пересечения по целым блокам 3×3; диагональные, Killer и нерегулярные судоку пока не поддерживаются. Учётные записи, история задач и гарантированный офлайн-запуск отсутствуют.

## Проверки

```sh
npm test
npm run build
npx playwright install chromium firefox webkit
npm run test:e2e
# Всё вместе после установки браузеров:
npm run verify
# Проверка именно статической сборки (сначала npm run build):
npm run test:e2e -- --config=playwright.preview.config.ts
```

Vitest проверяет оба размера, гипотезы и восстановление состояния, сохранение исходных чисел, единственность, отсутствие решений, конфликты и геометрию углов. Playwright проверяет реальные браузеры: Chromium, Firefox и WebKit в режиме iPhone; ручной ввод, паузу, отмену, PNG, загрузку и распознавание фотографии. Камера проверяется с тестовым видеопотоком: снимок → OCR → подтверждение → решение → PNG, а также отказ в разрешении, отсутствие и занятость устройства, пересъёмка, переключение и позднее разрешение после закрытия окна. Проверяются размеры первого экрана 1366×768, 1440×900, 390×844 и 320×568. Мобильная эмуляция и тестовый видеопоток не заменяют отдельную приёмку с настоящей веб-камерой и камерой физического телефона по доверенному HTTPS.

Дополнительно проверяются продолжение поиска после лимита вычислений, ошибка загрузки OCR-модели и поворот фотографии. Исходники форматируются командой `npm run format`; `npm run verify` также проверяет форматирование.

Составная геометрия проверяется на чистых изображениях схем из двух, пяти и восьми полей, а также на фотографии `tests/fixtures/composite8.png`. Тесты проверяют единое значение в пересечениях, противоречия между полями, навигацию через пустоты, исправление схемы и доступность кнопок при 320×568, 390×640 и 844×390.

Распознавание проверяется на сгенерированных печатных полях и исходной фотографии 16×16 из обсуждения проекта. Тест фотографии записывает отчёт о правильно распознанных печатных числах, ложных числах и требуемых исправлениях. Тест приватности проверяет отсутствие запросов к внешним HTTP-сервисам во время полного сценария OCR.

На контрольном снимке из журнала в режиме «Только печатные» измеряются правильно распознанные исходные числа и ложные заполнения. Это результат на одном снимке, а не обещание точности для других фотографий. Чистые контрольные поля обоих размеров проверяются на полное совпадение, включая обычный, нежирный шрифт 16×16 и предоставленное изображение со 100 синими числами.

На контрольной фотографии восьми полей режим «Только печатные» сравнивается с 96 вручную выписанными печатными значениями. Для них найдено несколько решений, что также проверено независимым алгоритмом exact cover. Рукописные пометки не включены в эталон. Файлы тестов и фотография не входят в сборку сайта.

Отдельный набор из **30 изображений из интернета** содержит фотографии газет, размытые снимки, заполненные от руки поля и сгенерированные сетки. Источники, лицензии, контрольные суммы и эталонные числа находятся в `tests/fixtures/web/`. Изначально использовались 20 изображений для настройки и 10 для отложенной проверки. Найденные при ней ошибки подавления шума затем исправлены; итоговые цифры относятся к уже известному набору, а не к независимой выборке. [Отчёт о точности и ограничениях](docs/ocr/README.md).

```bash
node scripts/fetch-ocr-corpus.mjs
OCR_CORPUS=1 npm run test:e2e -- tests/ocr-corpus.spec.ts --project=desktop
node scripts/report-ocr-corpus.mjs /tmp/sudoku-ocr-current
```

Тесты не обращаются к внешним сайтам: изображения уже сохранены локально. Скрипт загрузки нужен только для проверки контрольных сумм или восстановления файлов. Сеть и сервер для распознавания приложению не нужны.

## Локальная приёмка составных судоку

Работа ведётся в ветке `feature/overlapping-sudoku`. Перед публикацией требуется локальная проверка пользователем. Для быстрого знакомства откройте «Ещё → Составное · 8 полей», решите пример и сохраните изображение; затем загрузите свой снимок и проверьте схему и числа. Эта ветка не публикуется автоматически: отправка в `main` или ручной запуск Pages выполняется отдельно после приёмки.

## Сборка и публикация

```sh
npm run build
npm run preview
```

Готовый сайт находится в `dist/`. Сборка включает OCR-модель и локальные WASM-ресурсы. Открывать `index.html` напрямую через `file://` не следует: worker и WASM требуют HTTP-сервера.

Публикация настроена на **GitHub Pages**: https://archibaldart.github.io/SudokuMaster/.

Workflow `.github/workflows/pages.yml` запускается при отправке изменений в `main` или вручную через GitHub Actions. Он устанавливает Node.js из `.node-version`, выполняет `npm ci` вместе с подготовкой OCR-ресурсов, проверяет форматирование и решатель, собирает и публикует только папку `dist`. Репозиторий публичный; сайт доступен всем по HTTPS.

В Settings → Pages выбран источник **GitHub Actions**. Workflow использует встроенный `GITHUB_TOKEN`; отдельные ключи хостинга не требуются. Путь сайта определяется через `actions/configure-pages` и передаётся сборке как `SUDOKU_BASE_PATH`. Это сохраняет правильные адреса скриптов, workers и OCR-ресурсов внутри `/SudokuMaster/`. Локальный запуск по умолчанию остаётся на `/`.

Проверка сборки с тем же путём, что и на GitHub Pages:

```sh
SUDOKU_BASE_PATH=/SudokuMaster/ npm run build
SUDOKU_BASE_PATH=/SudokuMaster/ npm run test:e2e -- --config=playwright.preview.config.ts
```

Проверка опубликованного сайта без запуска локального сервера:

```sh
SUDOKU_DEPLOY_URL=https://archibaldart.github.io/SudokuMaster/ npm run test:e2e -- --config=playwright.preview.config.ts
```

Эти проверки включают решение, сохранение PNG, распознавание 9×9 и 16×16 и снимок с тестового видеопотока. Отдельно можно проверить настоящую камеру, открыв публичный адрес на телефоне.
